# 1. Project Overview

## Project Name

Fantasy Football AI Predictor

The name is temporary and may change later.

## Core Goal

Build a fantasy football application that predicts an NFL wide receiver's upcoming weekly full-PPR fantasy points using historical NFL data and machine learning.

The application will eventually include an AI fantasy football assistant that can use custom tools to analyze projections and answer questions such as:

* "How many points is this player projected to score?"
* "Should I start Player A or Player B?"
* "Why is Player A projected higher?"
* "How has this player's usage changed recently?"

The AI agent must use data and model outputs generated by this project rather than inventing projections itself.

# 5. Initial Prediction Scope

The first model predicts:

**Next-week full-PPR fantasy points for NFL wide receivers.**

Start with WRs only.

Do not generalize the first model across multiple positions.

## Full-PPR Scoring

Initial scoring should follow:

* Reception: 1 point
* Receiving yard: 0.1 points
* Rushing yard: 0.1 points
* Receiving touchdown: 6 points
* Rushing touchdown: 6 points
* Fumble lost: -2 points, when reliable data is available

Additional scoring rules should not be introduced without a reason.

# 11. Important Technical Principles

## Prevent Data Leakage

When predicting Week N, features may only use information available before Week N.

Never use full-season statistics when predicting an earlier week of that same season.

## Maintain a Baseline

The machine-learning model must be compared against a simple baseline.

A complicated model is not automatically better.

## Use Temporal Evaluation

NFL predictions involve ordered time data.

Evaluation should respect chronology rather than blindly randomly mixing future and past observations.

## Build Incrementally

A phase should work before introducing another major technology.

Bad:

```
broken ML
  +
unfinished API
  +
unfinished agent
  +
unfinished frontend
```

Good:

```
working data pipeline
       ↓
working baseline
       ↓
working ML model
       ↓
working API
       ↓
working agent
       ↓
working frontend
```

## Deterministic Code Before Agents

Tasks that can be performed reliably by ordinary Python functions should generally remain ordinary Python functions.

Use the AI agent for:

* interpreting user intent
* choosing tools
* combining multiple pieces of evidence
* generating explanations
* conversational interaction

Do not use an LLM where a deterministic calculation is more appropriate.
